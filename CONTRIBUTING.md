# Contributing to Workflow Intelligence

Thank you for helping improve Workflow Intelligence.

## Principles

Contributions should improve reproducibility, evidence quality, workflow usefulness, or developer experience.

Do not add code that invents evidence, customer validation, revenue, or execution authority.

## Development

1. Create a focused change.
2. Add or update tests.
3. Run the Community Edition test suite.
4. Keep environment-specific tooling outside the public core.
5. Document meaningful behavior changes.

## Pull requests

Explain the user problem, the evidence for the change, and the verification performed.

Small, reviewable pull requests are preferred.

## Public/private boundary

Local operator controls, credentials, model caches, private datasets, hosted infrastructure, and customer information do not belong in Community Edition commits.

## Evidence standard

A test can prove software behavior. It cannot prove real customer demand or revenue. Keep those claims separate.
