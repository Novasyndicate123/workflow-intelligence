# Security Policy

Workflow Intelligence should be operated with the same care as any system handling business-process information.

## Reporting

Do not publicly disclose sensitive vulnerabilities before a fix or coordinated disclosure path exists.

Use a private security contact provided by the eventual public project repository.

## Never commit

- API keys or passwords
- operator tokens
- customer records
- private datasets
- model credentials or caches
- machine-specific secrets
- production infrastructure configuration

## Security expectations

Changes should preserve evidence provenance, authorization boundaries, and human approval requirements.

A component must not silently gain external-send or external-execution authority through a convenience integration.

## Current release posture

This Community Edition is a staged release candidate. It has not been publicly published or granted production security commitments.

## Security contact

For private security reports, contact **workflowintell@gmail.com** rather than publishing sensitive details publicly.
